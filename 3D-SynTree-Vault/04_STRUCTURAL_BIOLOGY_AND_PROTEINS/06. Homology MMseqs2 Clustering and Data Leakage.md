# 06. Homology MMseqs2 Clustering and Data Leakage

### 1. What It Is

**Sequence homology** refers to evolutionary relatedness between proteins—proteins that share a common ancestor and thus have similar amino acid sequences. **Sequence clustering** partitions proteins into groups based on sequence identity, ensuring that homologous proteins do not appear in both training and test sets.

**Data leakage** occurs when information from the test set contaminates the training set, leading to inflated performance estimates that collapse on truly novel data.

### 2. Why It Exists

If you randomly split protein-ligand complexes into training and test sets, homologous proteins (e.g., different kinase variants with 80% sequence identity) will appear in both sets. The model can then "memorize" binding pockets from similar proteins during training and recognize them in the test set—this is not generalization, it's rote memorization.

This produces:
- **Inflated benchmark performance:** High test accuracy that doesn't reflect true novelty
- **False confidence:** Believing the model can design for new targets when it can only recognize familiar folds
- **Scientifically invalid conclusions:** Claims of generalization that don't hold on unseen protein families

### 3. How It Works

#### MMseqs2 Clustering Pipeline

**Step 1: Sequence alignment**
MMseqs2 computes fast local sequence alignments across all protein chains in the dataset using k-mer matching and ungapped alignment for speed.

**Step 2: Cluster formation**
Proteins sharing ≥ 30% sequence identity over an 80% alignment coverage window are placed in the same cluster. This threshold captures evolutionary relationships while separating distinct folds.

**Step 3: Union-Find connected components**
If Protein A is similar to Protein B, and Protein B is similar to Protein C, all three are placed in the same cluster using a Union-Find (disjoint-set) algorithm. This handles transitive relationships correctly.

**Step 4: Split assignment**
Clusters are assigned to train/validation/test splits as whole units—no cluster is split across partitions, ensuring zero homology leakage.

#### Cluster Threshold Criteria

| Criterion | Value | Rationale |
|-----------|-------|-----------|
| Sequence identity | ≥ 30% | Captures homologous relationships |
| Coverage window | ≥ 80% | Ensures alignment spans most of protein |
| Algorithm | MMseqs2 | Fast, scalable clustering |
| Split unit | Cluster (not individual protein) | Prevents leakage |

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| Sequence homology | Evolutionary relatedness between proteins |
| Sequence identity | Percentage of identical residues in alignment |
| Coverage | Fraction of sequence aligned |
| MMseqs2 | High-throughput sequence clustering algorithm |
| Union-Find | Disjoint-set data structure for transitive clustering |
| Connected component | Group of mutually related sequences |
| Data leakage | Test information contaminating training |
| Split manifest | File assigning clusters to train/val/test |
| unified_splits_30seq_id.parquet | 3D-SynTree's immutable split file |

### 5. What You Must Understand

- **30% identity is the "twilight zone."** Below 30%, proteins may have similar folds despite low sequence similarity. Above 30%, they are generally homologous. This threshold is empirically chosen to balance clustering granularity with split size.

- **Union-Find handles transitivity.** Without it, A-B and B-C pairs might be split across partitions even though A and C are clearly related through B.

- **Cluster-level splitting is non-negotiable.** Splitting individual proteins across train/test while keeping homologs together is the only way to prevent leakage.

- **Common pitfall:** Random splitting by complex rather than by cluster. This is the most common source of inflated benchmarks in structure-based drug design.

- **Common pitfall:** Assuming sequence identity thresholds are universal. Different protein families may need different thresholds (e.g., 25% for very divergent families, 40% for closely related ones).

### 7. Project Connection

The homology and data leakage concepts map directly to the 3D-SynTree codebase:

- **`scripts/run_mmseqs_split.sh`**: Shell script executing MMseqs2 clustering on the protein sequence dataset.

- **`scripts/split_clusters.py`**: Python script assigning MMseqs2 clusters to train/validation/test splits.

- **`unified_splits_30seq_id.parquet`**: The immutable split manifest generated by the pipeline, used by all training and evaluation scripts.

- **100-target test manifest** in `scripts/run_comparative_benchmark.py`: Held-out targets clustered at < 30% sequence identity for unbiased benchmarking.
