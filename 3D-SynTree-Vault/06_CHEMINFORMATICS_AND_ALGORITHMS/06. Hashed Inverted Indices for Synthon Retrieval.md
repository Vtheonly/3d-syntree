# 06. Hashed Inverted Indices for Synthon Retrieval

### 1. What It Is

A **hashed inverted index** is a hash-based data structure that maps composite keys (reaction family, reactive handle, molecular formula) to lists of candidate catalog synthons. Instead of scanning all 50,000 synthons for every reaction candidate, the index directly points to matching synthon IDs, reducing the search space from ~50,000 to ~50 per query.

### 2. Why It Exists

During trajectory extraction and generative rollout, the model needs to find synthons compatible with a given handle and reaction family. Scanning 50,000 synthons sequentially for every candidate is computationally prohibitive—especially when this lookup happens thousands of times per training batch.

The inverted index pre-computes compatible mappings, making retrieval O(1) instead of O(K) where K is catalog size.

### 3. How It Works

#### Index Structure

**Hash key:** (Reaction_Family, Reactive_Handle, Molecular_Formula_Hash)

- **Reaction_Family:** One of the 10 certified reaction types (e.g., "amide_coupling")
- **Reactive_Handle:** Handle class on the core (e.g., "carboxylic_acid")
- **Molecular_Formula_Hash:** Hash of the synthon's molecular formula (pre-filters by composition)

**Value:** List of synthon IDs matching all three criteria

#### Retrieval Process

1. Compute hash key from current state (reaction family, exposed handle, formula constraints)
2. Look up bucket in hash table
3. Retrieve candidate synthon IDs (~50 instead of ~50,000)
4. Validate each candidate with exact RDKit reaction execution
5. Select among validated candidates

#### Why Validation Is Still Required

The index is a **pre-filter, not a replacement** for validation. Hash collisions and approximate formula matching mean some retrieved candidates may not actually react. Every candidate must pass exact RDKit reaction execution before being accepted.

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| Hash table | Key-value mapping structure |
| Hash key | Composite key (reaction, handle, formula) |
| Compound bucket | List of synthon IDs matching a key |
| Candidate pre-filter | Index-based retrieval reducing search space |
| Exact validation | RDKit reaction execution to confirm compatibility |
| O(1) lookup | Constant-time retrieval vs O(K) linear scan |
| ~50 candidates | Typical bucket size vs ~50,000 full catalog |

### 5. What You Must Understand

- **The index is complementary to RDKit validation.** It narrows candidates but doesn't guarantee chemical validity. RDKit reaction execution is the final arbiter.

- **Hash key design affects performance.** A well-designed key (reaction + handle + formula) gives tight buckets. A poorly designed key (reaction only) gives bloated buckets with many false positives.

- **Molecular formula hash is a coarse filter.** It catches obvious mismatches (different atom counts) but doesn't capture connectivity or stereochemistry.

- **Common pitfall:** Treating index results as guaranteed valid. Always validate with RDKit before accepting a candidate.

- **Common pitfall:** Not updating the index when the catalog changes. The index must be rebuilt if synthons are added or removed.
