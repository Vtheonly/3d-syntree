# 01. SMILES and Canonical Molecular Graphs

### 1. What It Is

**SMILES** (Simplified Molecular Input Line Entry System) is a text-based notation for encoding molecular structures as ASCII strings. It represents molecules as graphs: atoms are nodes, bonds are edges.

For example:
- Ethanol: `CCO`
- Acetic acid: `CC(=O)O`
- Benzene: `c1ccccc1`
- Aspirin: `CC(=O)Oc1ccccc1C(=O)O`

SMILES uses:
- **Atom symbols:** C, N, O, S, etc. (lowercase c, n, o, s for aromatic)
- **Bond symbols:** - (single), = (double), # (triple), : (aromatic)
- **Parentheses:** Branching (CC(=O)O means C-C(=O)-O)
- **Ring closure digits:** c1ccccc1 (digit 1 closes the ring)
- **Chirality tags:** @ and @@ for tetrahedral stereocenters
- **Directional bonds:** / and \ for double bond geometry

### 2. Why It Exists

Computers cannot directly "see" molecular drawings. They need a compact, standardized, serializable format to store, transmit, and process molecular structures. SMILES is the most widely used format in cheminformatics because:

- **Human-readable:** Chemists can read and write SMILES
- **Compact:** Much smaller than 3D coordinate files
- **Standardized:** Supported by virtually all cheminformatics software (RDKit, Open Babel, ChemDraw, etc.)
- **Canonicalizable:** The same molecule always produces the same SMILES string

**Canonical SMILES** ensure that identical molecular graphs produce identical text strings, regardless of atom ordering in the input. This is essential for database lookup, duplicate detection, and reproducibility.

### 3. How It Works

#### SMILES Parsing

A SMILES string is read left to right:
1. Each atom symbol creates a node
2. Bond symbols (or implicit single/aromatic bonds) create edges
3. Parentheses open and close branches
4. Ring digits open and close ring bonds
5. Chirality markers specify tetrahedral configuration

#### Canonicalization

RDKit converts SMILES to canonical form using graph labeling algorithms (Morgan/Weininger):
1. Assign initial invariants to each atom (element, degree, charge, etc.)
2. Iteratively refine labels based on neighbor labels
3. Break ties using a canonical ranking
4. Output atoms in canonical order

The result: identical molecular graphs always produce identical canonical SMILES.

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| Atom tokens | Element symbols (C, N, O, c, n, o, s) |
| Bond tokens | -, =, #, : (single, double, triple, aromatic) |
| Branch parentheses | ( ) for branching |
| Ring closure digits | 1–9 for ring bonds |
| Aromaticity | Lowercase letters (c, n, o) for aromatic atoms |
| Chirality tags | @ and @@ for stereochemistry |
| Directional bonds | / and \ for double bond geometry |
| Canonical SMILES | Standardized atom ordering |
| Graph | Nodes = atoms, edges = bonds |

### 5. What You Must Understand

- **SMILES encodes 2D connectivity, not 3D geometry.** It tells you which atoms are bonded, but not their x, y, z coordinates. Converting SMILES to 3D requires distance geometry (ETKDG) (see [[03_SPATIAL_CHEMISTRY_AND_FORCE_FIELDS/05_Distance Geometry and ETKDG]]).

- **Canonical SMILES are unique per molecule.** Two different SMILES strings (e.g., `CCO` and `OCC`) canonicalize to the same string. This is how RDKit recognizes that they represent the same molecule.

- **Aromatic SMILES use lowercase.** `c1ccccc1` is benzene; `C1=CC=CC=C1` is the Kekulé form. Both represent the same molecule but the aromatic form is preferred.

- **Common pitfall:** Assuming SMILES preserves atom order. Canonicalization reorders atoms; the position of an atom in a SMILES string has no inherent meaning.

- **Common pitfall:** Forgetting stereochemistry. `C[C@H](O)N` and `C[C@@H](O)N` are different molecules (enantiomers). SMILES without chirality tags represents an unspecified or racemic mixture.

### 7. Project Connection

The SMILES concepts map directly to the 3D-SynTree codebase:

- **`canonical_smiles()`** in `syntree/data/fragmenter.py`: Converts molecules to canonical SMILES for storage and comparison.

- **`SynthonCatalog` DataFrame storage** in `syntree/chemistry/catalog.py`: Each catalog entry stores canonical SMILES as the primary identifier.

- **Replay validation** in 3D-SynTree: After a reaction, `canonical_smiles(product)` must equal `canonical_smiles(observed)` to verify that the reaction executed correctly.
