# 06. Training Algorithms and Stability

### 1. What It Is

Training a GFlowNet for 3D molecule generation involves several interacting algorithms:

1. **Forward policy training:** Learn P_F(a | s) to generate molecules
2. **Backward policy training:** Learn P_B(s | s') to decompose molecules
3. **Flow matching:** Optimize the detailed balance loss
4. **Curriculum scheduling:** Progress from easy to hard tasks
5. **Experience replay:** Sample from stored trajectories

Stability issues arise from the interaction of these components.

### 2. Why It Exists

GFlowNet training can fail in several ways:

- **Mode collapse:** The policy finds one good molecule and keeps generating it
- **Flow instability:** Flow values oscillate or diverge
- **Backward policy lag:** The backward policy can't keep up with the changing forward policy
- **Sparse rewards:** Most random trajectories get near-zero reward, providing no learning signal

### 3. How It Works

#### Training Loop

1. **Generate trajectories:** Roll out the current forward policy
2. **Store in replay buffer:** Add new trajectories
3. **Sample batch:** Draw trajectories from replay buffer
4. **Compute flow matching loss:** Detailed balance violation
5. **Update policies:** Gradient descent on forward, backward, and flow parameters
6. **Update curriculum:** Advance difficulty if performance thresholds met
7. **Repeat**

#### Stability Techniques

| Technique | Purpose |
|-----------|---------|
| Gradient clipping | Prevent exploding gradients |
| Learning rate decay | Stable convergence |
| Replay buffer | Decorrelate samples, prevent forgetting |
| Curriculum learning | Start easy, progress to hard |
| Target networks | Slow-moving copy for stability (optional) |
| Reward normalization | Keep rewards in reasonable range |

#### Common Failure Modes

| Failure | Symptom | Fix |
|---------|---------|-----|
| Mode collapse | Same molecule generated repeatedly | Check reward, increase entropy |
| Flow divergence | Flow values grow without bound | Check terminal condition F(s_T) = R(s_T) |
| Backward lag | Backward policy can't reverse forward actions | Train backward more frequently |
| Sparse rewards | Almost all rewards near zero | Curriculum learning, reward shaping |

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| Forward policy | P_F(a | s) - generation policy |
| Backward policy | P_B(s | s') - decomposition policy |
| Flow matching loss | Detailed balance objective |
| Replay buffer | Trajectory storage and sampling |
| Curriculum scheduler | Difficulty progression |
| Gradient clipping | Exploding gradient prevention |
| Learning rate schedule | Convergence stabilization |
| Mode collapse | Single-mode generation failure |

### 5. What You Must Understand

- **Forward and backward policies must be trained together.** The flow matching loss couples them; training one without the other doesn't work.

- **The replay buffer is critical for stability.** Without it, consecutive trajectories are highly correlated, leading to unstable updates.

- **Curriculum learning prevents early failure.** Starting with 2-step synthesis lets the model learn basic chemistry before attempting 4-step synthesis.

- **Common pitfall:** Using different learning rates for forward and backward policies without justification. They should typically use the same learning rate.

- **Common pitfall:** Not monitoring flow values. If flows diverge, the model is broken even if the loss looks OK.
