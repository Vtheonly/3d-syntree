# 04. Flow Matching Loss and Detailed Balance

### 1. What It Is

The **flow matching loss** is the objective function used to train GFlowNets. It measures how well the forward policy, backward policy, and flow function satisfy the detailed balance condition across all transitions in sampled trajectories.

**Detailed balance** states that for every transition from state s to state s' via action a:

$$\text{Forward flow} = \text{Backward flow}$$
$$F(s) \cdot P_F(a | s) = F(s') \cdot P_B(s | s')$$

### 2. Why It Exists

The flow matching loss ensures that the learned policy samples molecules proportional to their reward. Without this loss:

- The model might collapse to a single high-reward molecule (mode collapse)
- There's no guarantee that high-reward molecules are sampled more frequently
- The backward policy would be untrained and useless

The flow matching loss couples the forward policy, backward policy, and flow function into a single coherent system.

### 3. How It Works

#### Loss Computation

For a trajectory τ = (s_0, a_0, s_1, a_1, ..., s_T):

**Step 1: Compute log flows**
For each state s_t, compute log F(s_t) using the flow network (or a learned parameter).

**Step 2: Compute log ratios**
For each transition (s_t, a_t, s_{t+1}):
$$\text{ratio}_t = \log F(s_t) + \log P_F(a_t | s_t) - \log F(s_{t+1}) - \log P_B(s_t | s_{t+1})$$

**Step 3: Square and sum**
$$\mathcal{L}(\tau) = \sum_t (\text{ratio}_t)^2$$

**Step 4: Average over batch**
$$\mathcal{L} = \frac{1}{|\mathcal{B}|} \sum_{\tau \in \mathcal{B}} \mathcal{L}(\tau)$$

#### Terminal Condition

At terminal states s_T:
$$F(s_T) = R(s_T)$$

This means log F(s_T) = log R(s_T), providing the boundary condition.

#### Flow Parameterization

The flow F(s) can be:
- **Learned:** A neural network outputs log F(s) for each state
- **Tabular:** Flow values stored per state (only for small state spaces)
- **Parameterized:** F(s) = exp(MLP(state_embedding))

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| Flow matching loss | Objective for training GFlowNet |
| Log ratio | Log of forward flow / backward flow |
| Detailed balance | Forward flow = backward flow per transition |
| Terminal condition | F(s_T) = R(s_T) |
| Flow network | Network outputting log F(s) |
| Squared loss | Penalizes deviations from detailed balance |
| Batch averaging | Loss averaged over trajectory batch |

### 5. What You Must Understand

- **The loss is on log ratios, not raw ratios.** Working in log space prevents numerical underflow/overflow when probabilities are very small.

- **The terminal condition is critical.** F(s_T) = R(s_T) anchors all flow values. Without it, flows could be arbitrarily scaled.

- **All three components are trained together.** Forward policy, backward policy, and flow function are updated simultaneously to minimize the same loss.

- **Common pitfall:** Forgetting the terminal condition. Without F(s_T) = R(s_T), the flow matching loss has no scale reference.

- **Common pitfall:** Using different losses for forward and backward policies. They share the same flow matching loss.

### 7. Project Connection

The flow matching loss concepts map directly to the 3D-SynTree codebase:

- **`GFlowNetTrainer.compute_flow_matching_loss()`** in `syntree/engine/trainer.py`: Computes the flow matching loss from sampled trajectories.

- **`log_F` parameter** in `syntree/engine/trainer.py`: Learnable flow values for each state.

- **`syntree/engine/rl.py`**: Terminal reward R(s_T) used for the terminal flow condition.

- **`scripts/train_gflownet.py`**: Main training loop calling flow matching loss computation.
