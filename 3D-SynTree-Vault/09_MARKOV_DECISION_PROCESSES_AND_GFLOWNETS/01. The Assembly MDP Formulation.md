# 01. The Assembly MDP Formulation

### 1. What It Is

3D-SynTree formulates molecule generation as a **Markov Decision Process (MDP)** where an agent builds a molecule step by step by adding synthons to a growing core. The MDP is defined by:

- **States (S):** Partially constructed molecules with exposed reactive handles
- **Actions (A):** Attachment atom selection, synthon selection, reaction family, torsion angle
- **Transitions (T):** Applying a reaction to add a synthon, updating the core
- **Rewards (R):** Terminal reward based on binding affinity, drug-likeness, physical validity
- **Episode:** A complete synthesis from initial fragment to final molecule (3-4 steps)

### 2. Why It Exists

Molecule generation is inherently sequential: you can't add all synthons at once because each addition changes the available handles and the 3D geometry. The MDP formulation provides a principled framework for:

- **Sequential decision making:** Each step depends on previous steps
- **Credit assignment:** Determining which actions led to good/bad outcomes
- **Policy learning:** Learning a strategy for building molecules
- **GFlowNet extension:** Sampling molecules proportional to reward

### 3. How It Works

#### State Space

A state s_t at step t consists of:

| Component | Description |
|-----------|-------------|
| Core molecule | Partially built molecule (SMILES + 3D conformer) |
| Exposed handles | Available reactive sites for next attachment |
| Pocket context | Binding pocket features (from BipartitePaiNN) |
| Step counter | Current step t (0 to T_max) |
| Action history | Previous attachments, synthons, reactions |

#### Action Space

Each action has four components:

1. **Attachment atom:** Which core atom to attach at (categorical over core atoms)
2. **Synthon:** Which catalog synthon to add (categorical over ~50 candidates)
3. **Reaction family:** Which reaction type to use (categorical over 32 certified reactions)
4. **Torsion angle:** Dihedral angle for the new bond (continuous, von Mises distribution)

#### Transition Function

Applying action a_t at state s_t:
1. Select attachment atom on core
2. Select synthon from catalog
3. Apply reaction template (RDKit)
4. Set torsion angle for new bond
5. Embed product in 3D (ETKDG + MMFF94 + Kabsch)
6. Update exposed handles
7. Transition to s_{t+1}

#### Terminal State and Reward

At step T_max (3-4), the trajectory ends. The terminal reward R(s_T) is computed by ThreeDReward:

$$R = w_{\text{dock}} \cdot R_{\text{dock}} + w_{\text{contact}} \cdot R_{\text{contact}} + w_{\text{clash}} \cdot R_{\text{clash}} + w_{\text{drug}} \cdot R_{\text{drug}} + w_{\text{key}} \cdot R_{\text{key}} + w_{\text{div}} \cdot R_{\text{div}}$$$

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| State | Partially built molecule + context |
| Action | (attachment, synthon, reaction, torsion) |
| Transition | Reaction application + 3D embedding |
| Reward | Terminal scalar reward |
| Episode | Complete synthesis (3-4 steps) |
| Policy | P(a | s) - action selection |
| Value | V(s) - expected future reward |
| MDP | Markov Decision Process formalism |

### 5. What You Must Understand

- **The MDP is episodic, not continuing.** Each episode ends after 3-4 steps with a terminal reward. There is no continuing discount factor (γ = 1 for terminal rewards).

- **The state includes 3D geometry.** Unlike 2D generative models, the state includes 3D coordinates which affect available actions (steric constraints, torsion angles).

- **Actions are mixed discrete-continuous.** Attachment, synthon, and reaction are discrete; torsion angle is continuous. This requires hybrid action handling.

- **Common pitfall:** Treating the MDP as fully observable when some pocket information is hidden (e.g., water molecules, protein flexibility).

- **Common pitfall:** Ignoring that transitions are deterministic given an action (reaction application is deterministic), but the policy is stochastic.

Basic probability (conditional probability, expected value)

### 7. Project Connection

The MDP formulation maps directly to the 3D-SynTree codebase:

- **`ThreeDRSPEnvironment`** in `syntree/engine/environment.py`: Implements the MDP environment (states, actions, transitions, rewards).

- **`step()`** in `environment.py`: Executes one action and returns next state, reward, done flag.

- **`reset()`** in `environment.py`: Starts a new episode with an initial core fragment.

- **`syntree/engine/rl.py`**: Contains `ThreeDReward` class computing the terminal reward.

### 8. Required Depth

**Essential.** The MDP formulation is the foundation of the entire GFlowNet approach in 3D-SynTree.
