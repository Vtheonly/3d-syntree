# 03. Equivariant Vector Features and Scalar-Vector Mixing

### 1. What It Is

In SE(3)-equivariant neural networks, node features come in two types:

- **Scalars:** Rotation- and translation-invariant (atomic number, partial charge, hybridization state)
- **Vectors:** Rotation-equivariant, translation-invariant (force vectors, direction vectors, displacement vectors)

**Scalar-vector mixing** is the mechanism that allows information to flow between these two channels while preserving equivariance. Without mixing, scalars and vectors would be isolated computational pathways.

### 2. Why It Exists

Molecular properties have different transformation behaviors:

- **Energy** is a scalar: rotating a molecule doesn't change its energy
- **Force** is a vector: rotating a molecule rotates all force vectors
- **Dipole moment** is a vector: rotating a molecule rotates the dipole

A neural network must produce both types of outputs correctly. It must also allow scalar information (e.g., atomic charge) to influence vector outputs (e.g., force direction) and vice versa.

### 3. How It Works

#### Valid Operations (Preserve Equivariance)

| Operation | Input Types | Output Type | Example |
|-----------|-------------|-------------|---------|
| Scalar + Scalar | Scalar, Scalar | Scalar | Charge + charge |
| Scalar × Scalar | Scalar, Scalar | Scalar | Weight × charge |
| Scalar × Vector | Scalar, Vector | Vector | Gate × force direction |
| Vector + Vector | Vector, Vector | Vector | Force₁ + force₂ |
| Vector · Vector | Vector, Vector | Scalar | Dot product (energy from force) |
| ‖Vector‖ | Vector | Scalar | Norm (magnitude) |
| Cross product | Vector, Vector | Vector | Torque (pseudovector) |

#### Invalid Operations (Break Equivariance)

| Operation | Problem |
|-----------|---------|
| Scalar + Vector | Dimension/type mismatch |
| Vector × Vector (element-wise) | Not rotation-covariant |

#### PaiNN Scalar-Vector Mixing

In PaiNN layers, scalar messages gate vector updates:

1. Compute scalar message: m_s = MLP(s_i, s_j, d_ij)
2. Compute vector message: m_v = MLP(v_i, v_j) ⊗ u_ij
3. Scalar gate: g = σ(MLP(m_s))
4. Vector update: v_new = v + g · m_v (scalar-gated vector addition)
5. Scalar update: s_new = s + m_s + φ(‖m_v‖) (vector magnitude feeds into scalar)

The key: scalar g controls how much vector information m_v flows into the vector channel. The vector magnitude ‖m_v‖ feeds back into the scalar channel.

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| Scalar feature | Rotation-invariant (charge, atomic number) |
| Vector feature | Rotation-equivariant (force, direction) |
| Scalar gate | σ(MLP(scalar_message)) controlling vector flow |
| Gated vector update | v_new = v + g · m_v |
| Vector magnitude | ‖v‖ feeding into scalar channel |
| Dot product | Vector → scalar conversion |
| Cross product | Vector → vector (pseudovector) |

### 5. What You Must Understand

- **Scalars gate vectors, not the reverse.** In PaiNN, scalar messages produce gates that scale vector updates. Vectors influence scalars through their magnitudes (‖v‖), not through direct addition.

- **Rotation equivariance is preserved.** All valid operations transform correctly under rotation. If you rotate the input by R, all vector features rotate by R, and all scalar features stay the same. The output follows the same pattern.

- **Translation invariance is automatic.** Vector features are based on relative positions (r_j − r_i), so translating all atoms by t leaves them unchanged.

- **Common pitfall:** Adding a scalar to a vector. This is dimensionally and geometrically meaningless.

- **Common pitfall:** Element-wise vector multiplication. v₁ ⊙ v₂ is not rotation-covariant and breaks equivariance.

- **Common pitfall:** Treating cross products as regular vectors. Cross products are pseudovectors (axial vectors) that transform differently under reflections. Since 3D-SynTree uses SE(3) (no reflections), this is fine, but it matters for E(3).
