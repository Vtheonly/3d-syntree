# 01. Group Theory E3 SE3 SO3 SO2

### 1. What It Is

**Group theory** is the mathematical study of symmetry. In geometric deep learning, we use specific groups to describe how objects transform in space without changing their intrinsic properties:

- **E(3):** The Euclidean group — all rotations, translations, and reflections in 3D space
- **SE(3):** The special Euclidean group — all proper rotations (det = +1) and translations in 3D space (no reflections)
- **SO(3):** The special orthogonal group — all 3D rotations around the origin (det = +1)
- **SO(2):** The special orthogonal group in 2D — rotations in a plane

**Equivariance** means that transforming the input and then applying the model gives the same result as applying the model first and then transforming the output:

$$f(g \cdot x) = g \cdot f(x)$$

**Invariance** means the output does not change when the input is transformed:

$$f(g \cdot x) = f(x)$$

### 2. Why It Exists

Molecular systems are symmetric under rotation and translation. Rotating a protein-ligand complex by 45 degrees or translating it by 10 Å does not change its chemistry or binding affinity. A neural network that respects this symmetry:

- **Generalizes better:** It doesn't need to learn the same interaction at every rotation
- **Is data-efficient:** One training example covers all rotated/translated versions
- **Respects physics:** Binding energy does not depend on absolute position or orientation in space

3D-SynTree's models (BipartitePaiNN, torsion heads, torsion conditioning) are designed to be SE(3)-equivariant where needed (predicting vectors that rotate with the input) and SE(3)-invariant where needed (predicting scalar energies that don't change under rotation).

### 3. How It Works

#### SE(3) Transformations

A proper rigid-body transformation in 3D:

$$\mathbf{x}' = R\mathbf{x} + t$$

Where R is a 3×3 rotation matrix (RᵀR = I, det(R) = +1) and t is a 3D translation vector.

#### SO(3) Rotations

Rotations around the origin only (no translation):

$$\mathbf{x}' = R\mathbf{x}$$

SO(3) is a subgroup of SE(3) where t = 0.

#### SO(2) Planar Rotations

Rotations in a 2D plane:

$$\begin{bmatrix} x' \\ y' \end{bmatrix} = \begin{bmatrix} \cos\theta & -\sin\theta \\ \sin\theta & \cos\theta \end{bmatrix} \begin{bmatrix} x \\ y \end{bmatrix}$$

#### Equivariance vs Invariance

| Property | Definition | Example in 3D-SynTree |
|----------|------------|----------------------|
| Equivariant | f(g·x) = g·f(x) | Vector predictions rotate with input |
| Invariant | f(g·x) = f(x) | Scalar energy unchanged by rotation |

#### PaiNN Message Passing

BipartitePaiNN uses scalar and vector features:
- **Scalar features:** Invariant under rotation (atomic numbers, charges)
- **Vector features:** Equivariant under rotation (direction vectors, forces)

Messages mix scalars and vectors while preserving equivariance through operations like:
- Scalar × Scalar = Scalar
- Scalar × Vector = Vector
- Vector dot Vector = Scalar
- Vector × Vector (cross product) = Vector (pseudovector, actually)

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| E(3) | Euclidean group (rotations + translations + reflections) |
| SE(3) | Special Euclidean group (rotations + translations, no reflections) |
| SO(3) | 3D rotation group around origin |
| SO(2) | 2D rotation group |
| Equivariance | Output transforms same way as input |
| Invariance | Output unchanged under input transformation |
| Scalar feature | Rotation-invariant (e.g., atomic number) |
| Vector feature | Rotation-equivariant (e.g., force vector) |
| PaiNN | Equivariant message-passing neural network |

### 5. What You Must Understand

- **Equivariance is not invariance.** Equivariant outputs change predictably when inputs are transformed; invariant outputs don't change at all. 3D-SynTree needs both: vectors (forces, directions) must be equivariant, scalars (energies, probabilities) must be invariant.

- **Reflections change chirality.** E(3) includes reflections, which would invert molecular chirality. SE(3) excludes reflections because physical processes don't reflect molecules. 3D-SynTree uses SE(3), not E(3), to avoid chirality violations.

- **Scalar-vector mixing must be done correctly.** You cannot add a scalar to a vector (dimension mismatch). You can multiply a scalar by a vector, or take dot/cross products of vectors. PaiNN handles this correctly.

- **Common pitfall:** Using standard MLPs on 3D coordinates. Standard MLPs are neither equivariant nor invariant—they learn position-dependent features and fail to generalize across rotations.

- **Common pitfall:** Forgetting that translations don't affect internal molecular geometry. Centering the pocket at (0,0,0) removes translation dependence before neural processing.

### 7. Project Connection

The group theory concepts map directly to the 3D-SynTree codebase:

- **`BipartitePaiNN`** in `syntree/models/bipartite.py`: SE(3)-equivariant message passing over pocket atoms and ligand atoms, with scalar and vector features.

- **`ContinuousTorsionHead`** in `syntree/models/torsion_head.py`: Predicts torsion angles as scalar values (SE(3)-invariant outputs conditioned on equivariant intermediate features).

- **Cross-attention** in `syntree/models/policy.py`: Queries and keys use equivariant vector features; attention weights are scalar (invariant).

- **Pocket centering** (`syntree/data/curation.py`): Removes translation dependence by centering pockets at origin.
