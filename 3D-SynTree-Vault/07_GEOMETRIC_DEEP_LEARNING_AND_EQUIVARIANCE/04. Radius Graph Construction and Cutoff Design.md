# 04. Radius Graph Construction and Cutoff Design

### 1. What It Is

A **radius graph** connects atoms whose 3D distance is below a specified cutoff radius. Unlike k-nearest-neighbor graphs (which connect each node to its k closest neighbors regardless of distance), radius graphs connect all pairs within a physical distance, making them natural for molecular systems where interactions decay with distance.

### 2. Why It Exists

In protein-ligand systems, atoms interact primarily through short-range forces:
- **van der Waals:** Significant within ~4 Å, negligible beyond ~8 Å
- **Electrostatics:** Long-range but screened by solvent
- **Hydrogen bonds:** Require specific geometry within ~3.5 Å
- **Steric clash:** Occurs at distances below sum of van der Waals radii

Connecting all atom pairs in a pocket (O(N²)) is wasteful because distant atoms don't interact. A radius graph with an appropriate cutoff captures all physically relevant interactions while keeping the graph sparse.

### 3. How It Works

#### Radius Graph Construction

**Step 1: Compute pairwise distances**
For all pocket-ligand atom pairs, compute Euclidean distance:
$$d_{ij} = \|\mathbf{r}_i - \mathbf{r}_j\|_2$$

**Step 2: Apply cutoff**
Create edge (i, j) if d_ij < cutoff_radius

**Step 3: Store edge attributes**
For each edge, store:
- Distance d_ij
- Direction unit vector u_ij = (r_j − r_i) / d_ij
- Atom types of both endpoints

**Step 4: Build adjacency**
Sparse adjacency matrix or edge list for message passing

#### Cutoff Design Considerations

| Cutoff | Pros | Cons |
|--------|------|------|
| Too small (3 Å) | Very sparse, fast | Misses longer-range interactions |
| Too large (15 Å) | Captures all interactions | Dense graph, slow, noisy |
| 5–6 Å (typical) | Balanced | Misses some electrostatics |

In 3D-SynTree, the cutoff is 5.0 Å, capturing van der Waals contacts and hydrogen bonds while keeping graphs sparse.

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| Cutoff radius | Maximum distance for edge creation (5.0 Å in 3D-SynTree) |
| Pairwise distance | Euclidean distance between atom pairs |
| Edge list | Pairs of connected atom indices |
| Edge attributes | Distance, direction, atom types |
| Adjacency matrix | Sparse representation of graph connectivity |
| Degree | Number of edges per node |
| Sparsity | Fraction of zero entries in adjacency matrix |

### 5. What You Must Understand

- **Radius graphs are distance-based, not rank-based.** Unlike k-NN graphs, the number of edges per node varies. A buried pocket atom might have 20 neighbors; a surface atom might have 3.

- **Cutoff choice is a hyperparameter.** 5.0 Å was chosen for 3D-SynTree based on the typical range of van der Waals and hydrogen bond interactions. Different systems may need different cutoffs.

- **Direction vectors are edge attributes.** The unit vector u_ij = (r_j − r_i) / d_ij encodes direction information needed for equivariant message passing.

- **Common pitfall:** Using a fixed cutoff for all atom pairs. Some interactions (salt bridges) can extend beyond 5 Å; some (steric clash) are only relevant below 3 Å. A single cutoff is a simplification.

- **Common pitfall:** Forgetting that radius graphs change with conformation. As atoms move during torsion optimization, edges appear and disappear. The graph must be rebuilt or edges must be dynamically managed.

### 7. Project Connection

The radius graph concepts map directly to the 3D-SynTree codebase:

- **`radius_graph()`** in `syntree/models/bipartite.py`: Constructs radius graphs between pocket and ligand atoms with 5.0 Å cutoff.

- **`BipartitePaiNN.forward()`** in `syntree/models/bipartite.py`: Uses radius graph edges for message passing between pocket and ligand nodes.

- **Edge attributes:** Distance and direction vectors computed for each edge, used in PaiNN message computation.

- **`syntree/data/curation.py`**: Prepares pocket and ligand coordinates for radius graph construction.
