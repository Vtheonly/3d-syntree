# 02. Bipartite PaiNN Message Passing Architecture

### 1. What It Is

**BipartitePaiNN** is a geometric neural network architecture designed for protein-ligand systems. It extends the PaiNN (Polarizable Atom Interaction Neural Network) framework to bipartite graphs with two node types:

- **Pocket nodes:** Protein atoms from the binding pocket
- **Ligand nodes:** Atoms from the small molecule ligand

Edges connect pocket-ligand atom pairs within a cutoff radius (typically 5.0 Å). The network passes messages between these two node types, allowing pocket features to influence ligand representations and vice versa.

### 2. Why It Exists

Standard graph neural networks treat all nodes identically. Protein-ligand systems are fundamentally asymmetric:

- Pocket atoms are fixed in space (held by the protein scaffold)
- Ligand atoms are mobile (the molecule being designed)
- Pocket-ligand interactions are different from intra-pocket or intra-ligand interactions

BipartitePaiNN respects this asymmetry by:
1. Maintaining separate node embeddings for pocket and ligand
2. Passing messages only across the bipartite boundary (pocket→ligand and ligand→pocket)
3. Using SE(3)-equivariant operations so predictions respect molecular symmetry

### 3. How It Works

#### Node Features

Each node maintains:
- **Scalar features** (invariant): atomic number, charge, hybridization, etc.
- **Vector features** (equivariant): position-based direction vectors

#### Message Passing Steps

For each message passing round:

**Step 1: Edge construction**
Connect pocket atom i to ligand atom j if ‖r_i − r_j‖ < cutoff (5.0 Å)

**Step 2: Message computation**
For each edge (i, j):
- Compute distance: d_ij = ‖r_i − r_j‖
- Compute direction: u_ij = (r_j − r_i) / d_ij
- Message from scalar features: m_s = MLP_s(s_i, s_j, d_ij)
- Message from vector features: m_v = MLP_v(v_i, v_j) ⊗ u_ij

**Step 3: Aggregation**
Sum all incoming messages at each node

**Step 4: Node update**
Update scalar and vector features using gated updates:
- Scalar update: uses scalar messages and vector norms (‖m_v‖)
- Vector update: uses vector messages scaled by scalar gates

**Step 5: Readout**
Pool node features to produce graph-level predictions (affinity score, etc.)

#### Scalar-Vector Mixing (Key PaiNN Innovation)

The critical insight is that scalars can gate vectors:

- s · v: Scalar multiplies vector (gated vector update)
- v₁ · v₂: Dot product gives scalar (vector-to-scalar)
- ‖v‖: Vector norm gives scalar (magnitude)

This allows information to flow between scalar and vector channels while preserving equivariance.

### 4. What It Consists Of

| Component | Description |
|-----------|-------------|
| Bipartite graph | Two node types (pocket, ligand) with cross edges only |
| Cutoff radius | 5.0 Å for edge construction |
| Scalar features | Rotation-invariant node properties |
| Vector features | Rotation-equivariant node properties |
| Edge messages | Computed from source and target node features |
| Gated updates | Scalar-gated vector updates (PaiNN innovation) |
| Readout | Graph-level pooling for final predictions |
| SE(3)-equivariance | Respects rotation and translation symmetry |

### 5. What You Must Understand

- **Only cross edges.** Pocket atoms do not message other pocket atoms; ligand atoms do not message other ligand atoms. All information flows across the pocket-ligand boundary. This models the physical interaction between protein and ligand.

- **Vector features need direction.** A vector feature like a force direction rotates with the molecule. If you rotate the input pocket by 30 degrees, all vector features rotate by 30 degrees too. Scalar features (atomic number, charge) stay the same.

- **Gated updates enable scalar-vector mixing.** Without gating, scalars and vectors would be separate channels that never interact. The scalar gate (e.g., σ(MLP(scalar_message))) controls how much vector information flows into the scalar channel.

- **Common pitfall:** Passing messages within the same node type (pocket-pocket or ligand-ligand). This breaks the bipartite assumption and mixes intra-molecular geometry with inter-molecular interaction.

- **Common pitfall:** Treating vector outputs as scalars. A predicted force vector must transform under rotation; taking its magnitude loses directional information.

### 7. Project Connection

The BipartitePaiNN concepts map directly to the 3D-SynTree codebase:

- **`BipartitePaiNN`** in `syntree/models/bipartite.py`: Full implementation of bipartite message passing with scalar-vector feature pairs, cutoff-radius edges, and SE(3)-equivariant updates.

- **`syntree/models/bipartite.py`**: Contains `PaiNNLayer`, `BipartitePaiNN`, and radius-graph construction functions.

- **`forward()`** in `BipartitePaiNN`: Takes pocket and ligand point clouds, runs message passing, returns updated node embeddings.

- **Input to policy:** BipartitePaiNN outputs are consumed by the attachment head, synthon head, and torsion head in `syntree/models/policy.py`.
